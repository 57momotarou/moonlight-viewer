Moonlight 在庫レポート（2026-09-23）

【登録】
在庫は同じ時点のスクリーンショットを最大2枚まで追加できます。
2枚をまとめて解析し、重なって写る同じスロットは1回だけ数えるよう指示します。
同じ商品でも別スロットのスタックは合算します。商品・素・SPコインの数を確認して保存してください。
2枚の場合は数量の確認チェックが必要です。以前の画像は撮影日時も修正してください。

【照合】
商品＋対応する素＋甘いものの素を総数で比較します。
素1個から商品1個を作るだけでは総数は変わりません。
開始コイン＋区間の収集登録−終了コインを交換枚数の参考とします。
10枚→100素。終了在庫日時が2026-09-03 17:00より前の区間だけ10枚→50素です。
交換先は不明のまま、どの素へ交換しても残る最小の説明不能差を計算します。
別カテゴリ・別区間の増加で減少を相殺しません。無料配布・使用・移動で数字を合わせません。

【未報告コイン】
未報告のコインを自動で推定・従業員へ加算することはありません。
区間を開き「コイン報告・日時の確認」で全員分の報告を確認するまで、差0でも未判定です。
後から報告が届いた場合は、コイン登録で実際の収集・スタッシュへの入庫日時を入力してください。
在庫・請求書・コインが変われば再計算し、以前の確認を失効させます。

【その他売上】
金額だけの売上から個数・分類を推定しません。
共通の「食べ物・飲み物」項目は、読み取った個数・単価・金額を保ち、内訳不明で保存できます。
種類・個数が不明の区間では減少を不足と断定しません。分かった場合は伝票を編集できます。

【判定】
緑：記録上は問題なし。コイン報告を確認済みで、記録上の数量が整合しています。
赤：説明できない減少あり。記録条件を確認しても減少差が残っています。
黄：確認が必要。報告・数量・日時・読み取り等が未確定、または説明不能の増加があります。
原因や不正を行った人物を特定する判定ではありません。
判定カードと各区間を押すと詳細を開けます。HTMLレポートには全区間と記録を出力します。

【端末】
iPhoneは同期したデータの閲覧用です。確認の保存・伝票修正はWindowsで行ってください。
Windows更新は既存アプリを終了し、ZIP内のyuzucityの中身を上書きしてStart.vbsで起動します。
iPhone更新はyuzucityiphoneの中身を既存の公開先へ配置して画面を更新します。
