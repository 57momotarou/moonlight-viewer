Moonlight 在庫レポート（2026-09-13 更新）

【最初に見る場所】
「在庫」の先頭に大きな判定カードを表示します。カード全体を押すと理由と集計を開けます。
・緑「記録上は問題なし」：表示期間の在庫・販売・確認済みの入出庫が一致し、未解決の確認事項がない状態。
・赤「不足あり（記録上）」：未確定の入力がない区間で、商品・素またはコインの計算上の不足が残る状態。原因の断定ではありません。
・黄「確認が必要」：交換・入出庫や分類・日時等が未確認の状態。減少差があっても、照合後の不足には混ぜず「確認前の減少差」として残します。説明できない増加も確認対象です。
・灰「比較データ不足」：異なる日時の在庫が2回分そろっていない状態。
判定には期間を表示します。終了より後の記録は今回の判定対象外として先頭にも表示します。
実際の不正や持ち出した人を断定する機能ではありません。

【交換・入出庫の登録：Windows】
1. 「区間ごとの判定・交換の記録」を開き、対象の日時の行を押します。
2. 「交換・入出庫を登録／編集」を開きます。
3. 実際に在庫へ入れたコインの枚数を入力します。初期表示はその区間の正のコイン登録枚数です。
   従業員の実績として登録しただけで未入庫の場合は、実際の入庫枚数に直してください。
4. 素への交換回数を、交換先ごとに入力します。1回は10コインです。
5. コイン交換以外の補充、販売以外の使用・移動があれば、その数量と理由を入力します。
   素から商品を作るだけの変化、登録済みの店頭販売・デリバリーはここへ重ねて入力しません。
6. 「この内容を記録して再計算」を押します。確認済みの交換・入出庫が在庫の計算に反映されます。
登録後も同じ場所で編集できます。「入出庫の記録を解除」で確認前の計算へ戻せます。
保存先への書き込みに失敗した場合は確認済みに切り替えません。

【在庫とコインの計算】
商品＋対応する素の終了予定数
  ＝開始数＋確認済みの交換＋その他の補充−店頭販売−デリバリー−販売以外の使用・移動
コインの終了予定枚数
  ＝開始枚数＋実際の入庫−交換に使った枚数−交換以外の出庫
甘いものの素も独立して増減を確認します。素1個から商品1個を作る前提です。
照合後の不足・確認前の減少差・増加差はカテゴリ別・区間別に合計し、他の増加と相殺しません。
実在庫の増減（開始と終了の差）と、販売等を反映した区間別の差は別の数値です。
コインの入出庫が未確定なら「確認待ち」と表示し、未確認を「不足0枚」と表示しません。
在庫チェック履歴と詳細も、レポートと同じ交換・補充・使用を反映した計算を使います。

交換先が未確認の場合は「交換を仮定した減少差（参考）」を詳細に表示します。
期間全体の参考値＝全区間の減少差＋交換を仮定すると加わる差。交換がない区間の減少差も残します。
照合後の不足・確認前の減少差を含むため、別に加算しません。
例：10コインが減り、在庫が70個しか増えていない場合、新しい換算では30個不足する可能性があります。
実際に素100個へ交換したと記録し、他の未確定項目がなくなると、30個を照合後の不足として表示します。
コイン登録＝実際の入庫、コイン減少＝交換、と自動で確定することはありません。

【交換率の切替】
各区間の終了在庫日時が2026年9月3日17:00より前：10枚→素50個。
同時刻以降：10枚→素100個。9/3→9/4の在庫差分は100個で換算します。
複数区間は区間ごとに当時の交換率で計算してから合算します。

【その他売上・日時の確認】
お祭りの商品など、在庫が動く販売は、販売実績の詳細でカテゴリ・個数を割り振ってください。
金額だけから個数・カテゴリは推測しません。元のその他売上を二重に残さないよう金額も確認してください。
協賛金など、区間のその他・未分類売上がすべて在庫対象外の場合だけ、入出庫の編集欄でその確認にチェックし理由を記録できます。
時刻不明の記録は00:00として計算しますが、同じ日付の比較区間では、仮の00:00が区間外でも確認事項として残します。区間を開くと対象の記録を見られます。正確な時刻を入力して再計算してください。
同じ分の請求と在庫は、開始と同じ分は対象外、終了と同じ分は対象です。
実際にその順序だった場合は編集欄で前後関係を確認済みにできます。異なる場合は元記録の日時を修正してください。

【後から追加・修正した時】
登録順ではなく、保存された請求日時で区間を決めます。後日追加・手修正も再計算で反映します。
在庫・請求書・コイン履歴・比較区間が変わると、以前の入出庫確認は失効し、再確認が必要になります。
以前の入力値は編集欄に残しますが、確認し直すまで判定には使いません。
保存された実在庫を書き換えたり、再計算のたびに同じ販売を二重に引いたりしません。

【iPhone・出力】
iPhoneは同期・更新で取得した同じ判定と内訳を閲覧できます。入出庫の編集はWindowsで行います。
「レポートを保存」で、その時点の判定・計算・記録を詳細まで開いたHTMLを保存できます。

【デリバリーの日時】
日時が画像で読めない注文へ、読み込み時の現在時刻を自動で入れなくしました。
解析後の各行に実際の注文日時を入力してください。同じ日時の注文だけ、画像横の日時欄で一括指定できます。
日時未入力の注文があれば保存を止めます。一部だけ保存することはありません。
同じ注文番号を再読込し、画像に日時がない場合は、すでに保存されている日時を引き継ぎます。
以前に保存済みの日時は勝手に変更しません。レポートの9件は全件9/12 00:10なので、実際の日時をデリバリー履歴で確認してください。

【金額だけの請求書】
画像に請求合計があり、3カテゴリの個数とカスタム明細が空の場合、今後の画像解析では請求額をその他売上に補完します。
金額から個数・カテゴリは推測しません。
以前に保存された9/9の5件（請求額合計$8,900,000、売上内訳0）は、販売実績の詳細で元の請求書を見ながら修正してください。
その他売上15件（$26,180,000）も、商品を渡した請求ならカテゴリと個数の確認が必要です。
